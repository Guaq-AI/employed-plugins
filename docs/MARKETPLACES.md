## Conflicts and how they are resolved

- **Root `plugin.json`**: Agent Plugins (closed schema), Antigravity (name and description only) and Kiro all want it. The root file follows Agent Plugins, which Antigravity reads leniently; a strict Antigravity variant is built into `dist/`.
- **OAuth declaration in `mcp.json`**: OpenAI documents `extensions["com.openai"].auth` on each server, but Agent Plugins 1.0.0 closes the server object, so strict clients would skip it. The root `mcp.json` stays strict; only `dist/employed-openai-plugin.zip` carries the OAuth block.
- **Agents and commands**: not part of Agent Plugins 1.0.0, OpenAI and Microsoft ignore or reject them. Copilot reads agents from `com.github.copilot/agents/` (generated copies). Claude, Qoder, ZCode, OpenHands and Cursor read `agents/` and `commands/`.
- **Hooks**: deliberately none. OpenAI's directory and MiniMax reject them, and nothing here needs one.
- **Stdio launcher**: only offered as a documented fallback, pinned to an exact version, because the Claude directory holds unpinned or launcher-based servers for review.

## Remaining gaps (need the server work or a human)

- `https://jobs.guaqai.me/mcp` must answer 401 with a `WWW-Authenticate: Bearer resource_metadata=...` header, and ideally allow unauthenticated `initialize` and `tools/list`, so store scanners (Mistral, OpenAI, Claude, MiniMax) can discover tools. On 2026-10-11 it returned a bare 401 JSON body.
- Public URLs assumed: `/privacy-policy`, `/terms-of-service`, `/support`, `/connectors`, `/assets/brand/logo.svg`, `/assets/brand/icon-512.png`, `/.well-known/openai-apps-challenge`, `/.well-known/mcp-registry-auth`.
